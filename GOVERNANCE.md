# Governance

MAM is maintained by **norockstar**, its original author. GitHub issues and pull
requests are the usual place for technical discussion. There is no foundation,
steering committee or promised support service.

The maintainer reviews changes against the execution contracts, tests and
documented scope. Significant API or audible changes need a written proposal
and explicit review. Routine fixes stay small. Security and conduct concerns
use the private contact in the relevant policy.

Contributors retain attribution. Additional maintainers can be invited after
sustained contributions; document responsibility before granting access.
Disagreements should explain the concrete tradeoff and evidence. The maintainer
makes the final release decision.

Next community proposals: establish a reviewed issue backlog, publish
reproducible example renders as optional release assets, and recruit reviewers
for realtime ownership, DSP and documentation. These are plans, not claims that
such teams or processes already exist.
